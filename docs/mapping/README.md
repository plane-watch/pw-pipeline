# Mapping / Geocoding

## Overview

The `mapping` package provides geocoding capabilities - converting human-readable location strings (addresses, city names, landmarks) into geographic coordinates (latitude/longitude). This is primarily used for receiver location setup and configuration.

## Why Geocoding?

### The Use Case

**Aircraft tracking requires receiver location**:
- MLAT (Multilateration) needs 3+ receiver positions
- Coverage maps need receiver coordinates
- Distance calculations need reference point

**User-friendly input**:
```bash
# Users want to provide:
./pipeline --location "123 Main St, Seattle, WA"

# Not:
./pipeline --lat 47.6062 --lon -122.3321
```

**Benefits**:
- Easier configuration (no coordinate lookup)
- Reduces setup errors (wrong decimal places, swapped lat/lon)
- Human-readable config files

### Alternatives Considered

**Manual coordinate entry**:
- ❌ Error-prone (typos, wrong sign)
- ❌ Users must look up coordinates separately
- ✓ No API dependency
- ✓ No rate limits

**IP geolocation**:
- ❌ Very inaccurate (city-level, not building-level)
- ❌ VPN/proxy breaks it
- ✓ Free (GeoIP databases)
- ✓ Automatic

**OpenStreetMap Nominatim**:
- ✓ Free, open source
- ✓ Good coverage
- ❌ Fair use policy (1 req/sec)
- ❌ Self-hosting required for production
- ❌ Data quality varies by region

**Google Maps Geocoding API**:
- ✓ Excellent accuracy
- ✓ Global coverage
- ✓ Well-documented
- ❌ Expensive ($5/1000 requests after free tier)
- ❌ Terms of service restrictions

**HERE Maps Geocoding API**:
- ✓ Good accuracy (comparable to Google)
- ✓ Global coverage
- ✓ Generous free tier (250k req/month)
- ✓ Simple pricing ($1/1000 requests)
- ✓ No ToS restrictions on use case
- ❌ Less popular than Google

**HERE wins for**: Free tier sufficient for typical usage, good accuracy, simple

## HERE Maps Integration

### API Client

**Auto-generated client**:

// lib/mapping/here/*.go
// Code generated by OpenAPI Generator

**Source**: HERE Geocoding and Search API v7 OpenAPI spec

**Why auto-generated**: Reduces maintenance, stays in sync with API changes

**Regeneration**:
```bash
# If HERE updates API
openapi-generator generate \
  -i https://geocode.search.hereapi.com/openapi.yaml \
  -g go \
  -o lib/mapping/here
```

### API Key Management

**Setting API key**:
```go
import "plane.watch/lib/mapping"

func main() {
    mapping.SetHereMapsApiKey("YOUR-API-KEY-HERE")

    lat, lon, err := mapping.FindCoordinates("Seattle, WA")
}
```

**Why package-level variable**: Simple, single API key for entire application

**Security consideration**: Key stored in memory, ensure not logged/leaked

**Getting API key**:
1. Create account at https://developer.here.com/
2. Create project
3. Generate API key for "Geocoding and Search API v7"
4. Free tier: 250,000 requests/month

### Geocoding Request

**Function signature**:
```go
func FindCoordinates(location string) (lat, lon float64, err error)
```

**Example queries**:
```go
// Street address
FindCoordinates("1600 Pennsylvania Avenue, Washington DC")
// → 38.8977, -77.0365

// City name
FindCoordinates("Tokyo, Japan")
// → 35.6762, 139.6503

// Landmark
FindCoordinates("Eiffel Tower")
// → 48.8584, 2.2945

// Airport code (may not work reliably)
FindCoordinates("LAX")
// → Results vary
```

### Request Parameters

**Sent to HERE API**:
```go
client.DefaultApi.GeocodeGet(ctx).
    Q(location).       // Query string
    Limit(5).          // Max 5 results
    Lang([]string{"en"}).  // English language
    Execute()
```

**Why limit=5**: Balance between options and complexity
- Too low (1): Might miss correct result
- Too high (10+): Confuses user with too many choices
- 5: Reasonable compromise

**Why lang=en**: Consistent address formatting
- HERE returns localized names by default
- English provides predictable format
- Could make configurable for international deployments

### Response Handling

#### Single Result (Success)

**Clean case**:
```go
resp.Items = [
    {
        Title: "Seattle, King County, WA, United States",
        Position: { Lat: 47.6062, Lng: -122.3321 }
    }
]
```

**Returns**: `47.6062, -122.3321, nil`

**Validation**: Checks `GetLatOk()` and `GetLngOk()` to ensure coordinates present

**Edge case handled**: API might return result without coordinates (rare)

#### Multiple Results (Ambiguous)

**Common scenario**:
```go
FindCoordinates("Springfield")
// USA has ~30 cities named Springfield!
```

**Response**:
```go
resp.Items = [
    { Title: "Springfield, IL, United States", Position: {38.7817, -89.6501} },
    { Title: "Springfield, MA, United States", Position: {42.1015, -72.5898} },
    { Title: "Springfield, MO, United States", Position: {37.2090, -93.2923} },
    { Title: "Springfield, OR, United States", Position: {44.0462, -122.9814} },
    // ...
]
```

**Error returned**:
```
Multiple results were returned, please use a more specific value.
```Springfield, IL, United States``` coords: 38.78170,-89.65010
```Springfield, MA, United States``` coords: 42.10150,-72.58980
```Springfield, MO, United States``` coords: 37.20900,-93.29230
```

**Why this format**:
- User sees all options
- Can copy-paste more specific string
- Coordinates shown for manual fallback

**Trade-off**: Error message instead of "best guess"
- Alternative: Return first result (might be wrong)
- Current: Force user to be specific (safer)

#### No Results

**Scenario**: Location not found
```go
FindCoordinates("asdfjkl;qwerty")
```

**Error**: `"did not find that location"`

**Causes**:
- Typo in location string
- Very new location (not in HERE database)
- Non-standard naming (local names not in database)

#### API Failure

**HTTP error**:
```go
if httpResp.StatusCode != 200 {
    return 0, 0, errors.New("failed to lookup this location")
}
```

**Common status codes**:
- **401 Unauthorized**: Invalid API key
- **403 Forbidden**: API key lacks permission
- **429 Too Many Requests**: Rate limit exceeded
- **500 Internal Server Error**: HERE service issue

**Current handling**: Generic error, logged with status code

**Improvement opportunity**: Parse status code, return specific errors

### Error Checking Pattern

**Unusual error check**:
```go
if "" != err.Error() || httpResp.StatusCode != 200 {
```

**Why `"" != err.Error()`**: Checks if error message is non-empty

**Simpler alternative**:
```go
if err != nil || httpResp.StatusCode != 200 {
```

**Both work**, but `err != nil` is more idiomatic

## API Context and Authentication

**Authentication method**: API key in context

```go
apiKey := map[string]here.APIKey{
    "ApiKey": {
        Key:    hereMapsApi,
        Prefix: "",
    },
}
ctx := context.WithValue(context.Background(), here.ContextAPIKeys, apiKey)
```

**Why context**: HERE client expects authentication in context

**No prefix**: Some APIs use "Bearer" or "Token" prefix, HERE doesn't

**Security**: API key passed in query parameter (HTTPS encrypted)

## Configuration Patterns

### Option 1: Environment Variable

```go
func main() {
    apiKey := os.Getenv("HERE_API_KEY")
    if apiKey != "" {
        mapping.SetHereMapsApiKey(apiKey)
    }
}
```

**Usage**:
```bash
HERE_API_KEY="your-key" ./pipeline --location "Seattle, WA"
```

**Benefits**: Key not in code, easy for containers

### Option 2: CLI Flag

```go
&cli.StringFlag{
    Name:    "here-api-key",
    Usage:   "HERE Maps API key for geocoding",
    EnvVars: []string{"HERE_API_KEY"},
}

// In action:
mapping.SetHereMapsApiKey(c.String("here-api-key"))
```

**Usage**:
```bash
./pipeline --here-api-key "your-key" --location "Seattle, WA"
```

**Benefits**: Explicit, visible in help text

### Option 3: Config File

```yaml
# config.yaml
here_api_key: "your-key-here"
receiver_location: "Seattle, WA"
```

```go
cfg := loadConfig("config.yaml")
mapping.SetHereMapsApiKey(cfg.HereApiKey)
```

**Benefits**: Persistent, version-controlled (with .gitignore for key)

### Fallback to Manual Coordinates

**Recommended pattern**:
```go
var lat, lon float64
var err error

if location != "" {
    lat, lon, err = mapping.FindCoordinates(location)
    if err != nil {
        log.Error().Err(err).Msg("Geocoding failed")
        // Fall back to manual coordinates
        lat = config.ManualLat
        lon = config.ManualLon
    }
}

if lat == 0 && lon == 0 {
    log.Fatal().Msg("No location configured")
}
```

**Why**: Geocoding is convenience, not requirement

## Rate Limiting and Quotas

### HERE Free Tier

**Limits**:
- 250,000 requests/month
- ~8,000 requests/day
- No per-second rate limit documented

**Typical usage**:
- **Startup**: 1 request (receiver location)
- **Configuration changes**: Rare
- **Multi-receiver deployment**: N requests on startup

**250k/month is sufficient for**:
- 8,000 receivers starting once/day
- 250k configuration changes/month
- Essentially unlimited for typical use

### Exceeded Quota

**Symptom**: 429 status code

**Current behavior**: Generic error logged

**Mitigation**:
1. **Cache results**: Save geocoded coordinates
   ```go
   // config.yaml
   receiver_location: "Seattle, WA"
   receiver_lat: 47.6062  # Cached from geocoding
   receiver_lon: -122.3321
   ```

2. **Check cache first**: Skip API call if coordinates present

3. **Upgrade plan**: $1/1000 requests beyond free tier

### Production Best Practice

**Cache geocoded locations**:
```go
type Config struct {
    Location string  `yaml:"location"`
    Lat      float64 `yaml:"lat,omitempty"`
    Lon      float64 `yaml:"lon,omitempty"`
}

func GetCoordinates(cfg *Config) (float64, float64, error) {
    // Use cached if available
    if cfg.Lat != 0 && cfg.Lon != 0 {
        return cfg.Lat, cfg.Lon, nil
    }

    // Geocode and cache
    lat, lon, err := mapping.FindCoordinates(cfg.Location)
    if err == nil {
        cfg.Lat = lat
        cfg.Lon = lon
        saveConfig(cfg)  // Persist for next run
    }
    return lat, lon, err
}
```

**Why cache**: Avoid repeated API calls for same location

**Check before calling**:

if "" != hereMapsApi {

**Error**: `"you do not have Here Maps API provided"`

**Use case**: Allow deployment without geocoding

## Common Issues

### Invalid API Key

**Symptom**: Every geocoding request fails with 401

**Cause**: API key incorrect or expired

**Debug steps**:
1. Verify key at https://developer.here.com/
2. Check API key has "Geocoding and Search" permission
3. Ensure key not rate-limited or disabled

**Solution**: Generate new API key

### Ambiguous Location

**Symptom**: Error with multiple results

**Cause**: Location string not specific enough

**Examples**:
```go
FindCoordinates("Springfield")       // Ambiguous
FindCoordinates("Springfield, IL")   // Better
FindCoordinates("Springfield, IL, USA")  // Best
```

**Solution**: Add more context (state, country)

### Coordinates Not Found

**Symptom**: "did not find that location"

**Causes**:
1. **Typo**: "Seatle" instead of "Seattle"
2. **Non-English**: "München" might work better as "Munich"
3. **Too specific**: "Apartment 3B" not in database
4. **Very new**: Recently built locations

**Workarounds**:
1. Try less specific: "123 Main St, Seattle" → "Seattle, WA"
2. Use English name: "東京" → "Tokyo"
3. Fall back to manual coordinates

### Rate Limit Exceeded

**Symptom**: 429 status code

**Temporary solution**:
```bash
# Wait a few minutes, retry
sleep 300
./pipeline --location "Seattle, WA"
```

**Permanent solution**:
1. Implement caching (above)
2. Upgrade HERE plan if needed
3. Switch to self-hosted Nominatim

### Typical Usage Patterns

**Single receiver deployment**:
- 1 API call on first startup
- Cached coordinates for subsequent starts
- Effectively zero ongoing usage

**Multi-receiver deployment (100 receivers)**:
- 100 API calls on initial deployment
- Cached in configs, no ongoing usage
- Well within free tier

**Dynamic deployments** (receivers come/go):
- More API usage, still minimal
- Example: 10 new receivers/day = 300/month
- Still <1% of free tier

### Geocoding Accuracy

**Generally excellent for**:
- Major cities (exact)
- Street addresses in urban areas (within meters)
- Airports, landmarks (exact)

**Less accurate for**:
- Rural addresses (might be road midpoint)
- New subdivisions (not in database yet)
- Non-standard addresses ("near the old mill")

**MLAT consideration**: Accuracy matters
- Off by 100m: MLAT still works
- Off by 1km+: Consider manual coordinates
- Test MLAT performance after deployment

### API Key Security

**Don't**:
- Commit API key to git
- Log API key in debug output
- Share API key publicly

**Do**:
```gitignore
# .gitignore
config.yaml     # If contains API key
.env            # If using environment variables
```

```yaml
# config.example.yaml (committed)
here_api_key: "YOUR-KEY-HERE"  # Placeholder

# config.yaml (not committed)
here_api_key: "actual-key-abc123"
```

### Cost Monitoring

**Free tier is generous**, but monitor usage:

**HERE Developer Portal**: Shows request count

**Warning threshold**: Alert at 80% of free tier (200k/month)

**Cost beyond free tier**: $1/1000 requests
- 300k requests/month = $50/month
- 1M requests/month = $750/month

**For high-volume**: Consider self-hosted Nominatim
- Free, unlimited
- Trade-off: Setup complexity, maintenance, data updates

### Caching Layer

**Simple in-memory cache**:
```go
var geocodeCache = sync.Map{}

func FindCoordinatesWithCache(location string) (float64, float64, error) {
    // Check cache
    if cached, ok := geocodeCache.Load(location); ok {
        result := cached.(GeocodingResult)
        return result.Lat, result.Lon, nil
    }

    // Cache miss, geocode
    lat, lon, err := FindCoordinates(location)
    if err == nil {
        geocodeCache.Store(location, GeocodingResult{lat, lon})
    }
    return lat, lon, err
}
```

**Why**: Reduce API calls for repeated locations

**Trade-off**: Memory usage for large caches

**Better**: Persistent cache (file/database)
