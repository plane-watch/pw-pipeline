# pw_haproxy_api

`pw_haproxy_api` is a small control-plane sidecar for HAProxy used by
Plane Watch to:

1.  **Expose feeder connection status via HTTP** (per feeder api key/UUID)
2.  **Populate and maintain HAProxy map files** containing valid feeder
    API keys
3.  **Route MLAT feeders to the correct regional MLAT backend** based on
    feeder metadata

It connects to the HAProxy Runtime API to read live connection
statistics and to update HAProxy maps at runtime, and it connects to
NATS to learn which feeder API keys are currently
authorised.

------------------------------------------------------------------------

## What it does

### 1) HTTP API: feeder status

Provides a simple endpoint to query a single feeder's current connection
state:

-   `GET /api/v1/feeder/<uuid>`

Returns a JSON object describing:

- whether the feeder is currently connected via **BEAST** and/or **MLAT**
- byte counters (in/out) per connection (from HAProxy stick-table counters)
- connection duration and routing info (frontend/backend/server)
- last update time for the cached entry

Also provides: - `GET /healthcheck` → `200 OK`

### 2) Keep HAProxy maps in sync with authorised feeders

Maintains two HAProxy maps:

-   **BEAST map**: `api_key_to_runway_backend`
    -   Maps `feeder_uuid -> be_runway_adsb` (currently hardcoded; can
        be extended later)
-   **MLAT map**: `api_key_to_mlat_backend`
    -   Maps `feeder_uuid -> be_mlat-server-<region>` based on feeder
        `FID`

Maps are updated at runtime via HAProxy Runtime API commands.

### 3) Disconnect invalid feeders

When a feeder API key is no longer authorised, `pw_haproxy_api` can
terminate active sessions via the HAProxy Runtime API.

### 4) Periodic checkpoint writes

At a configurable interval (default 30 minutes), the current runtime
maps are written to disk so HAProxy can restart cleanly.

## Required HAProxy Configuration (Summary)

### Runtime API

    global
        stats socket ipv4@0.0.0.0:9999 level admin
        master-worker

### BEAST Frontend (TCP + TLS + SNI required)

    frontend fe_runway_adsb
        bind ":::12345" ssl crt /certs/"${HAPROXY_CERT_PW}" ssl-min-ver TLSv1.2
        mode tcp

        tcp-request inspect-delay 5s
        tcp-request content reject unless { ssl_fc_sni -m found }

        option contstats

        stick-table type string len 256 size 500k expire 30s store conn_cur,bytes_in_cnt,bytes_out_cnt
        tcp-request content set-var-fmt(sess.k) "%[ssl_fc_sni]|%[src]:%[src_port]"
        tcp-request content track-sc0 var(sess.k)

        use_backend %[ssl_fc_sni,lower,map(/haproxy_maps/api_key_to_runway_backend,be_reject)]
        default_backend be_reject

### MLAT Frontend (TCP + TLS + SNI required)

    frontend fe_runway_mlat
        bind ":::12346" ssl crt /certs/"${HAPROXY_CERT_PW}" ssl-min-ver TLSv1.2
        mode tcp

        tcp-request inspect-delay 5s
        tcp-request content reject unless { ssl_fc_sni -m found }

        option contstats

        stick-table type string len 256 size 500k expire 30s store conn_cur,bytes_in_cnt,bytes_out_cnt
        tcp-request content set-var-fmt(sess.k) "%[ssl_fc_sni]|%[src]:%[src_port]"
        tcp-request content track-sc0 var(sess.k)

        use_backend %[ssl_fc_sni,lower,map(/haproxy_maps/api_key_to_mlat_backend,be_reject)]
        default_backend be_reject

### Required Backends

-   `be_runway_adsb`
-   `be_mlat-server-<region>` (as needed)
-   `be_reject`
